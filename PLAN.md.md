# Master Dashboard — Planning & Build Workflow

Oct 2, 2026 · @Mashal Huraira

A step-by-step plan for building a single web dashboard that replaces all 10 CLI tools with a unified UI for managing your UAE moving company clients.

## What the Dashboard Actually Is

One Next.js web app running on your local machine (or a VPS) that replaces every CLI command with a click. You open `localhost:3000` in your browser and see a sidebar with your clients on the left, and the tools across the top — Content, Ads, SEO, GBP Posts, Images, Humanizer, Reports. Select a client, pick a tool, fill in options, hit Generate. Output appears in a preview pane, and you save, edit, export, or copy it.

The critical design decision is that the dashboard wraps the same generation logic the CLI tools would use — the Anthropic API calls, the prompt templates, the config schema. It is not a separate codebase. The CLI tools become library functions that the dashboard's API routes call. If you later want to run a batch from the terminal, the same functions still work.

The dashboard adds three things the CLIs cannot give you: a visual client management layer (add, edit, and browse clients without touching JSON files), a content history (every generated piece is saved and searchable), and a batch operations view (generate content for all clients at once and review it before exporting).

## Architecture

Four layers, each doing one job.

&#91;embedded content: Dashboard architecture · four layers from browser to external APIs\]

The architecture under the diagram in plain terms.

**Browser layer** — what you see. A Next.js App Router frontend with React pages, Tailwind for styling, and shadcn/ui components (buttons, forms, tables, tabs, dialogs). This is the only layer you interact with. It sends requests to the API routes below.

**API routes layer** — one route per tool. Each route (like `/api/content/gbp`, `/api/ads/rsa`, `/api/seo/audit`) receives a request from the frontend, validates the inputs, calls the core library function, saves the result to the database, and returns the generated content. These are Next.js API routes (or Server Actions) — no separate backend server needed.

**Core libraries layer** — the shared logic that does the actual work. The prompt templates, the Gemini client, the config schema parser, the humanizer rules, the output formatters. This is the same code the CLI tools would use. The API routes import and call these functions. If you want to run something from the terminal later, you call the same functions.

**External services layer** — things outside your app. the Gemini API for content generation, Google APIs (Search Console, Ads, GBP, Analytics) for data pulling and reporting, your database for storing clients and generated content, and the file system for saving exported files (CSV, XLSX, markdown, images).

The key principle: every tool shares the same client config and the same Gemini SDK instance. A client created in the dashboard is available to every tool. Content generated by any tool is saved to the same database and shows up in the client's content history.

**Client management CRUD** — the first working feature. A page at `/clients` that lists all your clients in a table. ## Phase 2 — Content Engine Module (Week 2)

The most-used module. It generates GBP descriptions, FAQ items, blog posts, and meta tags.

### UI layout

The `/content` page has four tabs along the top: GBP Description, FAQ Generator, Blog Post, Meta Tags. Each tab shows:

1. **Active client banner** — shows the selected client's name, emirate, and a "Change" link. Confirms you are generating for the right client.
2. **Options form** — different per tab. FAQ has a count slider (5–20 items) and a topic field. Blog has a topic field, a target keyword field, and a word count selector. GBP has a character limit display (750 chars). Meta Tags has a page selector (home, services, about, contact, area pages).
3. **Language toggle** — Arabic only, English only, or Both. Defaults to Both.
4. **Generate button** — calls the API route, shows a loading spinner with progress text ("Generating Arabic GBP description...").
5. **Output preview** — rendered markdown on the left, raw copyable text on the right. For "Both" languages, two columns side by side.
6. **Action bar** — buttons: Copy to Clipboard, Save to History, Export as Markdown, Humanize (sends it through the humanizer before saving), Regenerate.

### API route pattern

Every module follows this pattern:

```typescript
// app/api/content/gbp/route.ts
export async function POST(req) {
  const { clientId, language, options } = await req.json()
  const client = await db.client.findUnique({ where: { id: clientId } })
  const result = await generateGBP(client, language, options)  // core lib
  await db.generatedContent.create({                           // save to history
    data: { clientId, type: 'gbp', language, content: result, createdAt: new Date() }
  })
  return Response.json({ content: result })
}
```

The core `generateGBP()` function in `lib/generators/content.ts` builds the prompt from the client config, calls the Gemini API, and returns structured output. This function is the same one a CLI would call.

### Content history

Every generated piece is saved to the `GeneratedContent` table with the client ID, content type, language, timestamp, and the full text. The client's detail page at `/clients/[id]` shows a "Content History" tab — a searchable, filterable list of everything ever generated for that client. You can re-open, copy, or re-generate from any past item.

## Phase 3 — Ads Modules (Week 2–3)

Two tabs under `/ads`: Google Ads and Facebook Ads. Both follow the same UI pattern as the Content module but with ad-specific validation.

### Google Ads RSA tab

The form shows: emirate selector, service selector, campaign name field, and language toggle. When you hit Generate, the API returns a structured object: 15 headline variations (each showing a live character count that turns red at 31+), 4 description variations (red at 91+), pin suggestions, sitelink extensions, callout extensions, and structured snippets.

The preview shows headlines and descriptions in a mock Google ad preview card — you see exactly how ad combinations will look. Below the preview, an "Export to Google Ads Editor CSV" button produces a file you can bulk-upload to Google Ads Editor without any manual formatting.

The key UX detail: each headline and description is individually editable in the preview. You can tweak a word, and the character counter updates live. Only when you are satisfied do you hit Save or Export.

### Facebook Ads tab

The form shows: campaign objective (Traffic / Messages / Conversions), offer text (optional), target audience notes, and count slider (3–10 variations). Generate returns ad cards showing: primary text, headline (40 char limit), description, CTA type, and the pre-built WhatsApp deep link.

Each variation shows a mockup of how it will look in the Facebook feed — primary text above an image placeholder, headline and CTA button below. An "Export for Meta Ads Manager" button outputs a CSV in Meta's bulk upload format.

### Batch mode

Both tabs have a "Batch Generate" toggle. When on, it generates ads for all emirates a client serves in one pass. The output is grouped by emirate, and the CSV export creates one campaign per emirate — matching your standard campaign structure.

## Phase 4 — SEO Audit & GBP Posts Modules (Week 3)

### SEO Audit module

The `/seo` page has two views: Run New Audit and Audit History.

**Run New Audit** shows the client's website URL (from their config) and a "Start Audit" button. When clicked, the backend spawns a background job that crawls the site using Puppeteer. The frontend shows a real-time progress panel: "Crawling page 3 of 12... Checking schema markup... Running Lighthouse..." using Server-Sent Events or polling.

When the audit finishes, the result page shows a scorecard at the top (On-Page: 72/100, Schema: 45/100, Speed: 88/100, Indexation: 65/100), followed by sections for each category with specific issues and recommendations. Each issue has a severity tag (Critical / Warning / Info) and an "AI Fix Suggestion" button that generates a specific fix instruction using the Anthropic API.

The audit is saved to the database and shows in Audit History with the date, overall score, and a "Compare" button that diffs two audits side by side to show improvements.

**Technical detail**: the crawling and Lighthouse runs are CPU-intensive. Run them in a background worker (a separate Node.js process or a Bull/BullMQ job queue) so the dashboard stays responsive. The progress updates come through the job queue's events.

### GBP Posts module

The `/gbp-posts` page shows a calendar view (month grid) for the selected client. Each week needs at least one post. Empty weeks are highlighted in red.

**Generate Posts** button opens a dialog: how many weeks to fill, and whether to auto-pick categories or specify a theme. Generate fills the calendar with draft posts. Each post card on the calendar shows the Arabic text preview, the post type tag, and the CTA.

Click a post card to expand it: full Arabic and English text, the matching image prompt, and buttons to Edit, Approve, Copy, or Delete. An "Export Month" button outputs all approved posts as a spreadsheet with columns: Date, Text AR, Text EN, Post Type, CTA, Image Prompt.

## Phase 5 — Image Prompts, Humanizer & Reports (Week 4)

### Image Prompts module

The `/images` page shows the client's brand specs (colors, truck type, uniform, style) pulled from their config, and a generation form: image category (loading scene, happy customer, truck fleet, packing, before/after), count slider, and a custom scene description field.

Generated prompts appear as cards showing the full prompt text and a "Copy to Clipboard" button. If you connect a Gemini API key, add a "Render" button that sends the prompt to the image API and shows the generated image inline. Prompts are saved to history and tagged by category.

The brand specs section is editable from this page — if a client gets new trucks or changes their colors, you update it here and all future prompts reflect the change.

### Humanizer module

The `/humanizer` page has two modes.

**Paste mode**: paste any text into a large text area, pick a strictness level (Light / Medium / Strict), and click Humanize. The output shows a diff view — original on the left, humanized on the right, with changes highlighted. Below the diff, a "Score" indicator shows how AI-detectable the original was versus the result (0–100 scale).

**Batch mode**: select a client and a content type (all GBP descriptions, all FAQ items, all blog posts). The humanizer processes the entire batch and shows a list with before/after scores. You approve each one individually or "Approve All" to replace the originals in the content history.

The humanizer is also available as a button on every other module's output preview (the "Humanize" button from Phase 2). When clicked from another module, it sends the generated content through the humanizer and replaces the preview.

### Reports module

The `/reports` page shows a month selector and a client selector (or "All Clients"). For each client, it pulls data from connected Google APIs and generates a summary report.

The minimum viable version works without API connections: you paste the numbers manually into a form (this month's impressions, clicks, calls, GBP views, ad spend, conversions) and the Gemini API generates the narrative summary, key wins, areas to improve, and next-month recommendations. You export the report as PDF or send it by email.

The full version connects to Google Search Console, Google Ads, GA4, and GBP APIs (each client needs OAuth). The dashboard pulls the data automatically and you just click "Generate Report" to get the full analysis.

## Phase 6 — Client Onboarding Wizard & Site Template (Week 5+)

### Onboarding wizard

A step-by-step form at `/clients/new/wizard` that replaces the basic "Add Client" form from Phase 1. Five steps:

1. **Company Info** — name (EN + AR), emirate, areas, services, phone, WhatsApp, website, competitor URLs
2. **Brand Setup** — primary and secondary colors (color pickers), logo upload, truck type, uniform color, visual style preferences
3. **Content Preferences** — brand tone, key differentiators, years of experience, fleet size, any certifications or awards
4. **API Connections** — optional: Google Search Console, Google Ads, GA4, GBP API credentials for automated reporting
5. **Initial Generation** — checkboxes for what to generate immediately: GBP description, 10 FAQ items, first month of GBP posts, RSA copy for the primary emirate, 3 Facebook ad variations, 8 image prompts

On completing step 5, the dashboard runs all checked generators in sequence with a progress panel (like the SEO audit). The client arrives in the system with a full content library ready to review.

### Website template launcher

The `/sites` page lists client websites you have built or are building. A "New Site" button runs the scaffold process: it reads the client's config from the database, generates a Next.js project from your template (the Moving Company Starter Kit from the earlier playbook), pre-fills all content from the client's generated content library, and outputs a zip file or pushes to a new GitHub repo.

This module is the heaviest to build because it involves generating a complete Next.js project with dynamic pages, i18n, and SEO metadata. Build it last, after you have refined the site template separately through a few manual client builds.

## Tech Requirements

### Software you need installed

- **Node.js 18+** — the runtime for everything. Install via nvm.
- **npm or pnpm** — package manager. pnpm is faster for monorepos.
- **Git** — version control.
- **Claude Code** — `npm install -g @anthropic-ai/claude-code`. This is your build tool.
- **Redis** (optional) — only needed if you use BullMQ for the SEO audit background jobs. For MVP, skip Redis and use an in-memory queue.
- **Puppeteer** — installs its own Chromium automatically via npm. Needed for SEO audits and PDF export.

### Accounts and API keys

- **Gemini API key** — your main generation engine — you already have a paid key. Find it at aistudio.google.com → API keys. Estimated monthly cost at your volume: $5–15 (Gemini API pricing is pay-per-use).
- **Google Cloud project** (optional, for Reports module) — enable Search Console API, Google Ads API, GA4 Data API, and GBP API. Each client needs to grant OAuth access to your project.
- **(The same Gemini key handles both text generation and image rendering — no second key needed.**) — only if you want to render images directly from the dashboard.
- **GitHub account** (optional) — for the website template launcher to push generated sites to repos.

### Environment variables

Your `.env` file:

```
ANTHROPIC_API_KEY=sk-ant-...
DATABASE_URL=file:./dev.db          # SQLite for local dev
NEXTAUTH_SECRET=random-string       # If you add auth
GEMINI_API_KEY=...                  # Optional
GOOGLE_CLIENT_ID=...                # Optional, for OAuth
GOOGLE_CLIENT_SECRET=...            # Optional
```

### Hardware

The dashboard runs on any machine that runs Node.js. Your laptop is fine for development and personal use. If you want it running 24/7 or accessible from your phone, host it on a cheap VPS (Hetzner, DigitalOcean, or a $5/month droplet). The SEO audit module is the only CPU-heavy feature (Puppeteer + Lighthouse), and it runs in the background without blocking the UI.

### Hosting options

- **Local only** (simplest) — run `npm run dev` on your machine. Access at localhost:3000. Data lives in a local SQLite file. Fine for a solo operator.
- **VPS** — deploy on a $5–10/month server. Use PM2 to keep it running. Access from anywhere via your server's IP or a domain. Switch to PostgreSQL for reliability.
- **Vercel** (partial) — the frontend and API routes deploy easily. But Puppeteer (SEO audits) and background jobs do not run on Vercel's serverless functions. You would need a separate worker server for those.

Recommended starting point: local development with SQLite, then move to a VPS with PostgreSQL once the dashboard is stable.

## Database Schema

Six tables cover everything. Use Prisma ORM — you define the schema once and it generates the database, the TypeScript types, and the query client.

```
model Client {
  id            String   @id @default(cuid())
  name          String                          // English name
  nameAr        String                          // Arabic name
  slug          String   @unique                // URL-safe ID ("al-afnan")
  emirate       String                          // Dubai, Sharjah, RAK, etc.
  areas         Json                            // ["Al Nahda", "Al Majaz"]
  services      Json                            // ["furniture moving", "packing"]
  phone         String
  whatsapp      String
  website       String?
  brandColors   Json?                           // {primary, secondary}
  brandSpecs    Json?                           // {truckType, uniform, style, avoid}
  tone          String?                         // "professional, trustworthy"
  notes         String?
  apiCredentials Json?                          // Google OAuth tokens per service
  createdAt     DateTime @default(now())
  updatedAt     DateTime @updatedAt
  content       GeneratedContent[]
  audits        Audit[]
  posts         GBPPost[]
  jobs          Job[]
}

model GeneratedContent {
  id            String   @id @default(cuid())
  clientId      String
  client        Client   @relation(fields: [clientId], references: [id])
  type          String                          // gbp, faq, blog, meta, rsa, fb-ad, image-prompt
  subtype       String?                         // emirate name, service name, etc.
  language      String                          // ar, en, both
  content       String                          // The generated text (full)
  contentAr     String?                         // Arabic version if generated separately
  metadata      Json?                           // char counts, keyword, options used
  humanized     Boolean  @default(false)
  score         Float?                          // Humanizer AI-detection score
  createdAt     DateTime @default(now())
}

model Audit {
  id            String   @id @default(cuid())
  clientId      String
  client        Client   @relation(fields: [clientId], references: [id])
  url           String
  scores        Json                            // {onPage, schema, speed, indexation}
  findings      Json                            // Full structured findings
  recommendations Json                          // AI-generated recs
  createdAt     DateTime @default(now())
}

model GBPPost {
  id            String   @id @default(cuid())
  clientId      String
  client        Client   @relation(fields: [clientId], references: [id])
  scheduledDate DateTime
  textAr        String
  textEn        String
  postType      String                          // whats-new, offer, event
  cta           String                          // call, learn-more, book
  imagePrompt   String?
  status        String   @default("draft")      // draft, approved, published
  createdAt     DateTime @default(now())
}

model Job {
  id            String   @id @default(cuid())
  clientId      String?
  client        Client?  @relation(fields: [clientId], references: [id])
  type          String                          // seo-audit, batch-content, batch-ads, report
  status        String   @default("pending")    // pending, running, completed, failed
  progress      Int      @default(0)            // 0-100
  result        Json?
  error         String?
  createdAt     DateTime @default(now())
  completedAt   DateTime?
}

model PromptTemplate {
  id            String   @id @default(cuid())
  name          String   @unique                // gbp-description, faq-generation, etc.
  systemPrompt  String                          // The full system prompt
  fewShotExamples Json?                         // Array of example inputs/outputs
  version       Int      @default(1)
  updatedAt     DateTime @updatedAt
}
```

The `PromptTemplate` table is important — it lets you edit and version your system prompts from the dashboard instead of changing code. Add a `/settings/prompts` page where you can view and edit each prompt template, test it with a sample client, and save. When you improve a prompt through experimentation, the improvement is saved to the database, not lost in a code file.

## How You Will Use It Day to Day

### Morning routine (15 minutes)

Open the dashboard. The home page shows a summary: clients with GBP posts due this week (highlighted), any audits older than 30 days, and content generation counts for the month. Scan the GBP calendar across clients — any empty weeks in the next 7 days? Click Generate to fill them. Approve yesterday's drafted posts. Total time: 15 minutes for what used to be an hour.

### New client signs up

Open the onboarding wizard. Fill in five steps of company info. Check all the boxes in Step 5. Go make tea while the dashboard generates a GBP description, 10 FAQ items, a month of GBP posts, RSA copy, 3 Facebook ads, and 8 image prompts. Come back, review and edit the outputs, export what you need. A client that used to take 3–5 hours of initial content setup now takes 30 minutes of review.

### Weekly content work

Select a client from the global dropdown. Jump between tabs: generate a new blog post under Content, flip to Ads to generate RSA copy for a new emirate campaign, check the GBP Posts calendar. Each module remembers the active client, so you are never re-entering company names or re-selecting emirates. When you switch to another client, everything updates.

### Running an SEO audit

Open the SEO module, hit Start Audit, and continue working on other clients while the crawler runs in the background. A notification appears when it finishes. Open the report, review the scorecard, and use the "AI Fix Suggestion" buttons to generate specific fix instructions you can send to the client or implement yourself.

### Batch operations

End of month: open the Reports module, select "All Clients," and generate reports for everyone. The dashboard either pulls data from connected Google APIs or shows a quick form to paste the numbers client by client. Export all reports as PDFs.

Need GBP posts for all 20+ clients for the next month? Open GBP Posts, toggle "All Clients," hit Generate. Review and approve in bulk.

### Editing prompts

You notice the FAQ generator's output keeps using the phrase "Whether you're looking for..." — a classic AI tell. Open Settings, Prompt Templates, find the FAQ template, add that phrase to the "avoid" instructions in the system prompt. Every future FAQ generation for every client now avoids it. No code changes needed.

### What changes about your workflow

Before the dashboard, each content piece required: opening a chat with Claude, pasting client details, writing a detailed prompt, waiting, copying the output, pasting it somewhere. For 20+ clients doing multiple content types weekly, that is hundreds of copy-paste cycles.

With the dashboard, the client details are always loaded, the prompts are templated and refined, the output is previewed and exportable in place, and everything is saved to a searchable history. The work that remains is editorial — reviewing, tweaking, and approving. The mechanical repetition is gone.

Estimated time savings across all clients: 15–25 hours per month, once the dashboard is fully built and your prompts are dialed in.
